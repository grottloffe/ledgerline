# Changelog

## 0.2.0 — 2026-07-25

- **`docs/project/STATE.md`** — a generated ~60-line view of where the project stands: current milestone and exit criteria, what is in flight with its unverified acceptance criteria, what needs a decision from a person, blocked and ready work, the debt register, and recent journal entries.
  - Regenerated by the `SessionStart` hook, so freshness does not depend on anyone remembering.
  - Written only when the content changed, so opening a session does not dirty the working tree.
  - `check` regenerates and compares, reporting a stale *or* hand-edited STATE.md instead of silently trusting it.
  - `merge=ours` in `.gitattributes`, since merging a generated file is meaningless.
- New `sp.js state [--stdout]` subcommand.
- Feature dossiers are now parsed once during `load()` — status, opened date, and acceptance-criteria progress — shared by `check` and the STATE generator.
- PRD open questions are parsed and surfaced as work that needs a person.
- `check` reports how many acceptance criteria are unchecked on a feature marked done, not just that some are.

## 0.1.0 — 2026-07-25

First version.

- Ledger model under `docs/project/`: PRD, architecture, roadmap, decisions, follow-ups, lessons, journal, feature dossiers, milestone reviews.
- Eleven skills: `kickoff`, `resume`, `status`, `start-feature`, `finish-feature`, `decide`, `followup`, `lesson`, `milestone-review`, `roadmap`, and the `using-superproj` contract.
- `superproj-auditor` read-only agent for ledger-versus-repository drift.
- `sp.js` engine: `init`, `status` (markdown / brief / JSON), `check`, `next-id`, `today`, `paths`. No dependencies.
- `SessionStart` hook injecting a project brief, using exec-form for Windows safety.
- Union-merge `.gitattributes` for append-only ledger files.
